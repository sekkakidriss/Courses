Part 01

The retrieval problem

A collection can contain millions of documents. Retrieval is the process of selecting the documents most useful for a query.

Query → relevant documents

Given a query q and collection D, compute a score that allows documents to be ranked.

d* = arg maxd∈D score(q,d)

The central question is what score means. Different retrieval methods define it differently.

Three views of relevance
Words exact or related terms
Vectors semantic proximity
Structure entities and relationships
Important distinction
TF-IDF, BM25 and dense retrieval are retrieval methods. RAG is an architecture that can use one or several of them.
Part 02

TF-IDF: importance of a word

TF-IDF ranks documents using how often a term occurs and how rare that term is across the collection.

Formal definition

Term frequency:

TF(t,d) = ft,d / Σt′ ft′,d

Inverse document frequency:

IDF(t) = log(N / df(t))
TF-IDF(t,d) = TF(t,d) × IDF(t)
Interactive example

Documents containing the term: 3

Total documents: 10

—
Here TF is normalized by a fixed document length of 10.
Limitation: TF-IDF is lexical. A document saying “joblessness” may not match a query using “unemployment” unless the terms overlap.
Part 03

BM25: stronger lexical retrieval

BM25 keeps term matching but adds saturation and document-length normalization.

BM25(q,d) = Σt∈q IDF(t) · [ f(t,d)(k₁+1) / ( f(t,d)+k₁(1−b+b|d|/avgdl) ) ]

k₁ controls term-frequency saturation. b controls document-length normalization.




—
Why BM25? Repeating a term 100 times should not make a document 100× more relevant. BM25 introduces diminishing returns and accounts for unusually long documents.
Part 04

Dense retrieval: search by meaning

Text is mapped into vectors. Similar meanings should occupy nearby regions of the embedding space.

Representation
q → q⃗ ∈ ℝd
d → d⃗ ∈ ℝd

Cosine similarity:

sim(q,d) = (q⃗ · d⃗)/(‖q⃗‖‖d⃗‖)
Key idea: dense retrieval can match “unemployment” with “joblessness” because the model represents meaning rather than only exact strings.
Part 05

Hybrid retrieval: combine signals

Lexical and semantic retrieval have complementary strengths. A hybrid score combines them.

0.50
Shybrid(q,d) = α SBM25(q,d) + (1−α) Sdense(q,d)
At α=1 the system is purely lexical. At α=0 it is purely dense. In practice, score normalization may be required before combining scores from different systems.
Part 06

Entity retrieval

Instead of treating a question as only a bag of words, identify the entities it refers to and retrieve information attached to those entities.

Example

Query: “What activities belong to ISIC 62?”

Detected entity: ISIC 62
Entity type: industry classification
Entity-centered retrieval
q → entities → linked records/documents

Useful when identifiers, names, codes or structured concepts are more reliable than general semantic similarity.

Part 07

Graph retrieval: use relationships

Graph retrieval follows explicit relationships between entities. The retrieved context can therefore depend on paths, neighborhoods and multi-hop connections.

Nk(v) = {u : dist(u,v) ≤ k}

1-hop: direct neighbors.

2-hop: neighbors of neighbors.

Multi-hop: follow a path satisfying relationship constraints.

Difference from dense retrieval:
Dense retrieval asks “which vectors are close?” Graph retrieval asks “which entities are connected in a meaningful structure?”

Reranking: retrieve first, judge again

A fast retriever can produce a candidate set. A more expensive model can then compare the query and each candidate more carefully.

Candidate retrieval reduces the search space. Reranking improves the ordering of the most promising candidates.

Part 09

RAG: retrieval-augmented generation

RAG connects retrieval to a language model. Retrieval supplies evidence; generation uses that evidence to formulate an answer.

1 · Retrieve

Dk = Retrieve(q,D)

BM25 / dense / graph / hybrid
2 · Rerank

C = Rerank(q,Dk)

select best evidence
3 · Generate

A = LLM(q,C)

answer from context
Core distinction: RAG is not equivalent to vector search. A RAG system can contain lexical retrieval, dense retrieval, entity search, graph traversal, reranking and an LLM.
Part 10

Evaluation: did retrieval actually work?

Retrieval quality should be measured separately from the quality of the generated answer.

0.60 Recall@5
0.60 Precision@5
0.33 MRR
0.61 nDCG@5

Recall@K

Recall@K = relevant retrieved / total relevant

Precision@K

Precision@K = relevant retrieved / K

MRR

MRR = (1/|Q|) Σq∈Q 1/rankq

nDCG rewards putting highly relevant documents near the top of the ranking.
